Ниже — очищенная формулировка идеи: без переноса стратегии из cash в MTT и сразу для стола из 8 игроков.

## MTT Solver: основная идея

Цель — не решать весь турнир как одно гигантское дерево CFR. Вместо этого строится иерархический агент: он точно и контрфактически решает текущую раздачу за столом из 8 игроков, а долгосрочные последствия решений оценивает через модель состояния турнира и множество симуляций продолжения.

Оптимизируется не chipEV и не само попадание в деньги, а ожидаемая турнирная выплата ($EV). Бабл — важная часть состояния: он меняет стоимость риска, но не становится искусственной конечной целью.

## Архитектура

```text
Текущее состояние MTT
        │
        ├─ Локальный 8-max poker solver
        │    └─ CFR / MCCFR / Deep CFR:
        │       стратегия и контрфактические значения в раздаче
        │
        ├─ Tournament-state model
        │    └─ стадия, блайнды, ante, выплаты, players left,
        │       hero stack, эффективные стеки за столом,
        │       агрегированное распределение стеков турнира
        │
        ├─ Stack-distribution transition model
        │    └─ вероятностный переход турнира к следующему состоянию;
        │       не симулирует каждого участника турнира поимённо
        │
        └─ Tournament value function V(T)
             └─ оценивает ожидаемую выплату из состояния T
```

### 1. Локальная игра

Базовая игра — сразу 8-max NLHE. Локальный solver получает карты, позицию, историю ставок, банк, блайнды, стеки всех восьми игроков и турнирный контекст.

CFR нужен здесь по своему прямому назначению: сравнивать альтернативные действия в условиях неполной информации. Контрфактические значения относятся прежде всего к веткам текущей раздачи, а не требуют строить полное контрфактическое дерево всего турнира.

### 2. Состояние турнира

Состояние `T` должно содержать только то, что меняет стратегическую цену фишек:

```text
T = (
  уровень блайндов и ante,
  структура выплат,
  число оставшихся игроков,
  число мест в деньгах,
  hero stack,
  стеки и позиции игроков текущего 8-max стола,
  агрегаты поля: средний стек, медиана, перцентили,
  число коротких стеков,
  стадия турнира и близость к ITM
)
```

Не нужно хранить и просчитывать траекторию каждого игрока во всём поле. Для решения текущей ситуации достаточно корректно моделировать статистически значимое окружение и его изменение.

### 3. Модель переходов

После раздач модель перехода оценивает:

```text
P(T_next | T, action, outcome)
```

Она обновляет стек героя по фактическому результату и вероятностно изменяет остальное поле: число игроков, распределение стеков, давление блайндов и близость к выплатам. Это заменяет невозможную симуляцию полного дерева тысяч участников.

### 4. Функция турнирной ценности

`V(T)` отвечает на вопрос: какую ожидаемую турнирную выплату имеет герой из данного состояния?

Она используется для оценки действий локального solver:

```text
Q(T, a) =
  ожидаемая ценность текущей раздачи
  + ожидаемая турнирная ценность последующего состояния
```

Поэтому действие с лучшим chipEV может быть отвергнуто, если оно ухудшает $EV около бабла, при сильном ICM-давлении или при неблагоприятном распределении коротких стеков.

### 5. Обучение

Обучение состоит из множества независимых турниров-эпизодов:

1. Запускается MTT с заданной структурой и 8-max столами.
2. Агент играет раздачи, локально применяя CFR-подобное обучение.
3. Завершившийся турнир даёт сигнал по реальной выплате.
4. При вылете начинается новый независимый турнир, а не искусственное продолжение ветки за выбывшего героя.
5. По rollouts обучаются policy, value function и модель переходов.

Такой подход сохраняет корректную работу с неполной информацией внутри раздач и заменяет неосуществимое дерево целого MTT статистической оценкой продолжений.

## Ключевая исследовательская гипотеза

Можно ли достаточно хорошо обучить `P(T_next | T, a)` и `V(T)`, чтобы локальный 8-max CFR-solver принимал почти такие же решения, как если бы видел полную будущую динамику турнира?

Итоговая формула:

```text
MTT Solver =
  8-max local CFR solver
  + tournament-state model
  + stack-distribution transition model
  + tournament value function
  + repeated tournament rollouts
```

Это не «CFR решает весь MTT» и не «RL учится просто доходить до бабла». Это локальный 8-max покерный solver, чьи решения направляются обученной оценкой долгосрочного $EV турнира.
