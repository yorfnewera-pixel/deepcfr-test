# 111 — Баг харнесса: четыре руки мерили частоту рейза, а не сайзинг

> Дата: 2026-08-16. Следует за #110. Пересмотр всех замеров `tools/sizing_oracle_ab.py` (v8→v13).

---

## 1. Два бага в `sizing_oracle_ab.py`

### Баг 1 — руки oracle/uniform всегда рейзили

`play_hand` (до починки): если герой на узле и `legal[3] > 0` (рейз легален), рука
`sizing_source` **принудительно рейзила**, не спрашивая `choose_action`:

```
if player == hero and sizing_source is not None:
    legal = agent.get_legal_action_mask(state)
    if legal[3] > 0:
        ... action = raise ...
```

Blueprint (`sizing_source=None`) шёл через `choose_action` и решал честно. Следствие —
таблица raises из старых отчётов: **841 / 813 / 827 против 156**. Три руки рейзили 100%
легальных узлов, блюпринт 18%. `blueprint − uniform` и `oracle − blueprint` мерили
**разницу в частоте рейза**, а не качество выбора размера.

### Баг 2 — ev считался по-разному

`OracleSizing.policy`: `ev = np.nanmean(filled[subset])` (простое среднее). Конвейер:
`ev = Σ(slot_weights·q_anchor)` (взвешенное по стратегии). Фраза «оракул на тех же
таргетах» была неверна — это две разные величины.

---

## 2. Починка

1. **`play_hand`**: действие (рейз/чек/фолд) выбирает `choose_action`; рука влияет только
   на РАЗМЕР рейза, когда выпал рейз.
2. **`OracleSizing.policy`**: `ev` по умолчанию **weighted** (по стратегии `advantage_sizing_net`,
   как конвейер v13). Добавлен `--ev-mode {mean,weighted}` для A/B.

Контроль: raises у четырёх рук сходятся в пределах ~10% (smoke 50 раздач: 18/18/18/19;
полный прогон iter 30: 150/151/154/156).

## 5. Открытый вопрос

Сеть (blueprint) ≈ uniform на всех итерациях, хотя оракул на тех же таргетах стабильно
значим (потолок `oracle_mc − blueprint` = +33 → +31 → +19 → +5). Почему сеть не выучивает
таргеты, которые оракул доказывает как хорошие?

Гипотеза (из #110 §7.5): вырождение таргета при 1 кредитуемом анкере — 48% строк имеют ровно
один кредитуемый анкер, у 94% из них `regret ≈ 0`. Согласуется с тем, что `oracle_mc − uniform`
убывает с итерацией (таргеты вырождаются по мере обучения). Но это требует отдельной проверки.

## 7. Почему сеть не учится: разложение буфера + харнесс (офлайн, v13 iter 30)

### 7.1. Разложение таргета по группам `credit_mask.sum()`

`r_i = grounded − ev_true` (анкеро-специфичный сигнал), `c = ev_true − ev_learned` (общая
компонента), `R_i` = сырой таргет в буфере.

| группа | строк | % вырождены (clamp→0) | std(r_i) | std(c) | std(R_i) |
|---|---|---|---|---|---|
| 1 | 478 506 (48%) | 96.4% | 0.000 | 0.000 | 0.104 |
| 2 | 286 357 (29%) | 29.3% | 0.556 | 0.249 | 0.744 |
| 3 | 235 137 (23%) | 11.8% | 0.806 | 0.433 | 0.943 |

Группа 1 вырождена **тождественно** (`r_i = 0`, один анкер сам себе baseline), `std(R_i)=0.104`
— не сигнал, а остаток частичной коррекции (`weight<1`) + бутстрап-член в обучении
(`deep_cfr.py:2787-2795`: `target = fresh·(previous·discount + regret) + (1−fresh)·previous`).

### 7.2. Харнесс A/B (300 шагов, batch 256, `sizing_train_harness.py`)

| вариант | base RATIO | итог RATIO |
|---|---|---|
| все строки (`--min-credits 0`) | 1.159 | 1.171 |
| `credit_mask.sum() >= 2` | 1.159 | 1.151 |
| `>= 2` + `--only-fresh` | 1.159 | **1.102** |

`RATIO = TV(net)/TV(uniform)`, гейт `< 0.8`.

### 7.3. Вывод

`RATIO` не опускается ниже 1.0 ни в одном варианте. Фильтр мусорных строк (группа 1) и фильтр
свежести **не решают** — интерпретация `RATIO` требует калибровки потолка, см. §9.

## 8. Проверка бутстрапа (`--no-bootstrap`) — гипотеза не подтвердилась

В `sizing_train_harness.py` добавлен `--no-bootstrap` (таргет = чистый `regret` без
`target_net(s)·discount`). Результат (v13 iter 30, 300 шагов, batch 256, `>= 2` кредитуемых):

| вариант | base RATIO | итог RATIO |
|---|---|---|
| `>= 2` (с бутстрапом) | 1.159 | 1.151 |
| `>= 2` + `--no-bootstrap` | 1.159 | 1.108 |
| `>= 2` + `--no-bootstrap` + `--only-fresh` | 1.159 | **1.071** |

Убрав бутстрап-член, RATIO улучшился лишь 1.151 → 1.108 → 1.071, но **не опустился ниже 1.0**.
Вывод: бутстрап `target_net(s)` — не главный виновник. Даже в максимально идеальных условиях
(чистый таргет без бутстрапа, только строки `>= 2` кредитуемых, только свежие, 300 шагов) сеть
остаётся дальше от таргета, чем равномерный выбор.

### Итог всех офлайн-проверок (§7–§8)

Опровергнуты по отдельности: мусорные строки группы 1 (C), дефицит свежих сэмплов (A),
общий сдвиг `c` (B, по построению в v13), и бутстрап-член. `RATIO` стабильно `>= 1.0`.

## 9. Калибровка RATIO и три проверки на баг индексации

### 9.1. Потолок метрики (офлайн, v13 iter 30)

| замер | значение |
|---|---|
| RATIO условного среднего (потолок запоминания, 0.5% дубликатов) | **0.65** |
| RATIO оракула (медиана) | 0.0 — совпадает с таргетом **по построению** |
| TV(policy_target, uniform) | 0.407 |

`TV(mean, визит) = 0.258` против `TV(uniform, визит) = 0.395`: условное среднее ближе к таргету,
чем uniform (0.65 < 0.8), то есть метрика жива. Но 0.65 — граница **зазубрившего** (дубликатов в
буфере 0.5%), а не то, чего обязана достигать сеть, обобщая на состояния, виденные один раз.

Замер «оракул = таргет» **тавтологичен**: после ev-правки v13 `regret = grounded − mean(grounded)`
по кредитуемым, и оракул считает то же из того же буфера (аналог «B устранён по построению»).

### 9.2. Три проверки на баг индексации/выравнивания — все отрицательные

| проверка | результат | вывод |
|---|---|---|
| знак согласия per-row | `corr(logit, R)` median 0.578, frac_neg 0.41 | нет систематического минуса |
| in-sample RATIO | 1.185 | сеть хуже uniform даже на виденных строках |
| перестановка анкеров | 1.202 (хуже реального 1.185) | порядок слотов не поехал |

### 9.3. Финальный вывод

Баг индексации/выравнивания **не подтверждён**. Сеть учится (corr 0.578, порядок слотов верный),
но `RATIO >= 1.0`, потому что сеть предсказывает гладкое условное среднее (MSE-оптимально), а
`RM(гладкого)` дальше от `RM(шумного сэмпла)`, чем uniform: **правильная усадка штрафуется
TV-метрикой**. Опровергнуты по отдельности: мусорные строки (C), дефицит свежих сэмплов (A),
сдвиг `c` (B), бутстрап, баг индексации. Открыт вопрос несоответствия MSE-обучения (сглаживает)
и RM/TV-политики (требует резкости): в игре оракул с резкими MC-регретами бьёт uniform
(+6.8…+44), сеть с гладким средним — нет. Гейт по **EV** (а не TV) остаётся способом проверить
реальную пользу правок.
