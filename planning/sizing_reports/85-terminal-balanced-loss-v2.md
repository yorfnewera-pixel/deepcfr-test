## 0. Pre-registered критерии (зафиксированы ДО запуска)

### Мотивировка

#84 показал что max_norm=100 даёт OK на iter 100, но relapse к iter 200-300 идентичен #73. #84b relapse analysis выявил механизм: advantage/regret-сеть делает полный flip fold↔raise (advantage fold: -7.93 → +0.53) из-за накопления сэмплов с нулевым reward для raise.

#83 (balanced loss v1) тестировался при max_norm=1.0 и получил CLOSED WARN (raise 3.0%) — Q был слишком сжат, дифференциация отсутствовала.

**Гипотеза #85:** При max_norm=100 (fit_ratio 0.10-0.21, в 5-10× лучше базы) terminal-balanced loss взвешивает Q-цели так, что terminal reward для raise (сейчас 0.0 для ВСЕХ raise-сэмплов) получает больший вес, компенсируя структурный дисбаланс delayed-reward и замедляя/предотвращая коллапс advantage-сети.

**(b) Behavior guardrail на КАЖДОМ чекпоинте:** verdict=OK, raise_freq ≥ 40%, unique_anchors = 15/15, top-2 sizing mass ≤ 55%, анкер 0.10 ≤ 15% массы.

### Режим проверки

### Интерпретация результатов

- **PASS:** balanced loss + max_norm=100 = стабильная конфигурация. Далее шаг 4 (Huber + n-step/MC) на этой базе.
- **PARTIAL:** balanced loss смягчает/отодвигает relapse → косвенное подтверждение что взвешивание terminal vs non-terminal помогает, но не достаточно. Усилить → нормализация целей (шаг 4).
- **FAIL:** balanced loss не влияет на механизм relapse → причина глубже (regret-накопление H3 из #84b). Шаг 4 — нормализация + annealing.
