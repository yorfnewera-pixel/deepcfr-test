# Bug #61: Схлопывание sizing в анкер 0.10 (feedback loop через sparsify)

**Severity:** HIGH

**Дата обнаружения:** 2026-06-04

**Чекпоинт:** multi_checkpoint_iter_700

---

## Симптомы

На итерации 700 анкер `0.10` занимает **84.5%** всех рейзов:

```
0.10:  1640 / 1940  (84.5%)
0.25:     0          (0%)
0.33:     0
0.50:     1
0.66:     6
0.75:   250          (12.9%)
остальные: 1-13 каждый   (<1%)
unique_anchors: 13 (но 11 из них в единичных сэмплах)
raise_freq: 20.3%
```

Фактически модель использует ровно два сайзинга: 0.10 и 0.75.
Даже 0.25 — прямой сосед 0.10 — ни разу не выбран.

---

## Root Cause: Training feedback loop через sparsify(top_per_bucket=1)

### Механизм

1. `_smooth_sizing_target_by_bucket` вычисляет Q-derived веса для 15 анкеров
2. `_sparsify_sizing_target_by_buckets(top_per_bucket=1)` обнуляет ВСЁ кроме:
   - одного анкера из small bucket (индексы 0-4)
   - одного анкера из medium bucket (индексы 5-9)
3. Разреженный target записывается в `sizing_strategy_buffer`
4. `train_strategy_sizing_anchor_network()` обучает `strategy_sizing_net` на KL-дивергенции с этим target'ом

**Результат:** для 13 из 15 анкеров target = 0, loss contribution = 0, gradient = 0.
Сеть получает обучающий сигнал **только для 0.10 и 0.75**.

### Feedback loop

```
strategy_sizing_net → softmax: 88% на 0.10
       ↓
sparsify(top_per_bucket=1) → training target: [90% 0.10, 10% 0.75, 0% всё остальное]
       ↓
KL-loss тренирует сеть предсказывать именно это распределение
       ↓
сеть ещё сильнее bias'ится в 0.10
       ↓
(повтор)
```

Сеть не «любит» 0.10 — она **никогда не видела градиентов** для других анкеров малого бакета.

## Bucket masses

```
bucket | sizes                        | raw_mass | sparse_mass
small  | 0.10, 0.25, 0.33, 0.50, 0.66 |  0.8837  |  0.8961
medium | 0.75, 1.00, 1.25, 1.50, 1.75 |  0.1067  |  0.1055
large  | 2.00, 2.25, 2.50, 2.75, 3.00 |  0.0096  |  0.0000  ← полностью обнулён
```

Large bucket полностью выпал — `top_buckets=2`, а масса large < medium всегда.

---

## Fix

**Конфиг:** `sizing_target_top_per_bucket: 1 → 2`

Теперь в training targets будет 4 анкера вместо 2:
- Small bucket: 0.10 + 0.66 (или что модель предскажет вторым)
- Medium bucket: 0.75 + 1.75

Это даёт ненулевые градиенты для анкеров, которые сейчас игнорируются.

### Изменённые файлы

| Файл | Изменение |
|------|-----------|
| `config.yaml` | Добавлен `sizing_target_top_per_bucket: 2` |
| `src/utils/config.py` | Дефолт изменён с 1 на 2 |
| `diagnose_sizing.py` | Добавлены функции: `filter_raise_states`, `evaluate_q_all_anchors`, `simulate_sparsify`, `analyze_sizing_collapse`, `print_collapse_report`, флаг `--collapse` |

## Оставшиеся риски

1. **1.50 — потенциальный новый коллапс.** Сейчас 47% — не критично, но нужен мониторинг на 500+, 1000+ итерациях. С `top_per_bucket=2` feedback loop слабее, но не исключён.

2. **Large bucket всё ещё обнуляется sparsify.** `top_buckets=2`, а large стабильно третий по массе (~18%). Решение: `sizing_target_top_buckets: 2 → 3` — даст градиенты всем трём бакетам.

3. **raise_freq ×2.3** — модель стала агрессивнее. Ожидаемо для 100 итераций, нормализуется с обучением.
