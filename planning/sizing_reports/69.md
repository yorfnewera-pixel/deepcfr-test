# Bug #69: Target-net для bootstrap sizing_q + коррекция диагностики source2

## Статус: FIXED

## Описание

После #67 и #68 диагностика показала:

1. source2 (lookahead bootstrap) монотонно дрейфует вверх (`source2_intra_anchor_range` 1.03→7.39) — классическая
   deadly-triad положительная обратная связь: `_bootstrap_sizing_value` считает V(s) через текущие live-сети,
   создавая moving target.

2. Метрика `source2_flatness` мерила **intra-anchor** разброс по состояниям (pre_max - pre_min внутри одного anchor),
   а не различимость между anchors. Рост 1.03→7.39 означал "source2 стал волатильнее по состояниям", а не "различает anchors".

3. Verdict `OK` врал при barbell-collapse и падении raise_freq.

## Изменения

### 1. Target-net в `_bootstrap_sizing_value`

**Файл:** `src/core/deep_cfr.py` — метод `_bootstrap_sizing_value`

При флаге `sizing_q_bootstrap_target_net=True` bootstrap использует замороженные сети:

```python
if self.sizing_q_bootstrap_target_net:
    adv = self.target_net(state_t)[:, :self.num_actions]   # вместо advantage_net
    q_vals = self.q_target_net(q_t)                         # вместо q_net
```

Зеркалит фикс #66 для `q_net`. Разрывает deadly-triad положительную обратную связь,
не создавая новых сетей: `q_target_net` и `target_net` уже существуют.

### 2. Коррекция диагностики source2

**Файл:** `tools/checkpoint_tools.py` — `run_sizing_q_target_diag_stats`

Старая метрика переименована:

```text
source2_flatness → source2_intra_anchor_range
```

Добавлена новая cross-anchor метрика:

```json
"source2_cross_anchor": {
  "mean_range": 0.095,
  "mean_std": 0.024,
  "argmax_anchor": 0,
  "n_anchors_represented": 15
}
```

Где:

- `mean_range` — разброс средних target'ов source2 между анкорами (различает ли)
- `mean_std` — стандартное отклонение средних между анкорами
- `argmax_anchor` — какой anchor source2 считает лучшим
- `n_anchors_represented` — сколько анкоров представлено

### 3. Verdict gates

**Файл:** `tools/checkpoint_tools.py` — `compute_verdict`

- CRITICAL: один anchor > 90% сыгранных sizing
- WARN: raise_freq < 25% (ранее порог был 5%)
- Убран старый порог 60% (слишком мягкий)

### 4. Config

**Файл:** `config.yaml`

```yaml
sizing_q_bootstrap_target_net: false
```

Default OFF для backward compatibility. Для нового прогона включать в ON.

### 5. Тесты

**Файл:** `tests/test_hybrid_outcome_sampling.py`

Добавлены 3 теста (41/41 passed):

- `test_bootstrap_sizing_value_uses_target_net_when_flag_on` — флаг ON → target-сети
- `test_bootstrap_sizing_value_uses_live_nets_when_flag_off` — флаг OFF → live-сети
- `test_checkpoint_saves_bootstrap_target_net_flag` — сохранение в чекпоинт

## План валидации

3. Сравнить:
