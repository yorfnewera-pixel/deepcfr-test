# Bug #66: Стабилизация q_net через reward scaling + target network

## Статус: FIXED

## Описание

q_net страдал от двух структурных дефектов:

1. **Reward не нормирован.** В `q_buffer` reward записывался сырым (`±200` при stake=200, bb=2).
   Сеть обучалась на MSE масштаба `200^2 = 40000`, давая loss 1000-3000 без снижения.
   `sizing_q` при этом делил на pot — рассинхрон масштабов.

2. **Нет target network.** `train_q_network` делал TD-bootstrap через `self.q_net(next_states_t)` —
   та же сеть, которая обучается. Это классическая дивергенция: сеть гонится за движущейся целью.
   target_net уже был у `advantage_net`, но для `q_net` отсутствовал.

q_net loss 1000+ делал поверхность Q нестабильной → sizing/OS-lookahead строились на шумной основе.
Коллапс ставок в 0.10 был симптомом, не первопричиной.

## Изменения

### 1. Reward scaling для q_net

**Файл:** `src/core/deep_cfr.py`

Добавлен атрибут `q_reward_scale` (по умолчанию `'bb'`) и метод `_get_q_reward_unit()`.

В `train_q_network` reward делится на `reward_unit` при обучении:

```python
reward_unit = self._get_q_reward_unit()
rewards_t = torch.from_numpy(rewards.copy()).to(self.device) / reward_unit
```

CFR/regret/sizing target не затронуты — только q_net учится в нормализованных единицах.

### 2. Target network для q_net

Добавлен `self.q_target_net` — замороженная копия `q_net`.
В `train_q_network` bootstrap теперь:

```python
next_q = self.q_target_net(next_states_t)  # вместо self.q_net
```

Синхронизация каждые `q_target_update_interval` итераций через `_sync_q_target_net()`.

Чекпоинт сохраняет и загружает `q_target_net`. Если в старом чекпоинте нет — синхронизируется из `q_net`.

### 3. Конфиг

**Файл:** `config.yaml`

```yaml
big_blind: 2.0          # базовый атрибут агента (ранее отсутствовал)
q_reward_scale: bb       # нормализация reward для q_net
q_target_update_interval: 100  # периодичность синхронизации target-сети
```

### 4. Тесты

**Файл:** `tests/test_hybrid_outcome_sampling.py`

Добавлены 6 тестов:
- `test_train_q_network_scales_rewards_by_big_blind` — проверка scaling
- `test_train_q_network_bootstraps_from_q_target_net` — target net для bootstrap
- `test_q_target_net_sync_replaces_weights` — синхронизация весов
- `test_checkpoint_saves_q_target_net` — сохранение в чекпоинт
- `test_load_checkpoint_restores_q_target_net` — загрузка из чекпоинта

Обновлён `test_train_q_network_uses_separate_perspectives` под новую архитектуру (q_target_net для bootstrap вместо q_net).

Результат: 26/26 passed.

## Что не трогалось

- `hybrid_os_epsilon_*` — пока 0.6 perpetually. Будет отдельным фиксом после проверки стабилизации Q.
- `anchor_sizes`, `sizing_inference_mode`, `sizing_min_prob`, `_normalize_sizing_q_target` — sizing логика не менялась.
- `hybrid_os_importance_weight_clip` — и так не активен (weights ≤5, clip=20).

## Порядок дальнейших действий

1. Перетренировать, смотреть `LossQNetwork` — должен упасть с тысяч до десятков.
2. Если всё ещё пилит/растёт — увеличить `q_target_update_interval` или добавить Polyak averaging.
3. Если Q стабилен, отдельной правкой: eps decay `0.5 → 0.1`.
4. Только после этого смотреть sizing collapse как самостоятельную проблему.
