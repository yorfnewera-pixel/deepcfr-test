# Полные эпохи для CFR-буферов

> **Для агента:** использовать `subagent-driven-development` или `executing-plans`. Сначала написать failing tests, затем минимально изменить training loops. Не менять формулы CFR-targets или sizing K-collapse; изменить lifecycle sizing advantage на fresh-only и заменить fixed-step sampling на полные эпохи.

**Цель:** перевести action, sizing strategy, sizing advantage и sizing-Q обучение с фиксированного числа случайных batch на полные проходы по текущему содержимому буфера с сохранением существующего дисконтирования и bootstrap-формул.

**Архитектура:**

- `advantage_buffer` очищается между итерациями, потому что action advantage использует `target_net` для переноса накопленного regret.
- `strategy_buffer`, sizing strategy buffer и sizing-Q replay остаются persistent и продолжают вытеснять старые samples.
- `sizing_advantage_buffer` очищается между итерациями, как и action advantage: он содержит только новые CFR-regret текущей итерации, а накопленное прошлое переносит `sizing_target_net`.
- Каждая обучающая функция получает настоящие эпохи: за одну эпоху каждый доступный sample используется ровно один раз, максимум один раз в каждом epoch.
- Старые samples не получают специального reservoir-приоритета. Existing iteration weights сохраняются для strategy buffers; advantage buffers используют bootstrap через target networks.

**Начальные значения эпох:**

```yaml
advantage_epochs: 20
strategy_epochs: 3

sizing_advantage_epochs: 3
sizing_strategy_epochs: 3

sizing_q_epochs: 3
```

`20` оставляем только для action advantage, потому что там это уже текущий рабочий режим. Для остальных сетей начинаем с `3`, чтобы не увеличивать training budget в сотни раз относительно нынешних 20 случайных шагов. После первого smoke/A-B запуска количество эпох можно поднять до `5`, если loss и качество улучшаются.

Action Q не включать в план как активный компонент: в текущем конфиге:

```yaml
use_q_baseline: false
```

Но код для Q и sizing-Q перевести на общий full-epoch механизм, чтобы при включении Q поведение было предсказуемым.

## Task 3: Общий helper для полных проходов

**Файлы:**

- Modify: `src/core/deep_cfr.py`
- Test: `tests/test_training_regressions.py`

Добавить приватный helper, например:

```python
def _full_epoch_batches(self, size, batch_size, epochs):
    """Возвращает индексы всех строк без повторений в каждой эпохе."""
    effective_batch = min(int(batch_size), int(size))
    for epoch in range(int(epochs)):
        permutation = np.random.permutation(size)
        for start in range(0, size, effective_batch):
            yield epoch, permutation[start:start + effective_batch]
```

Требования:

- каждая строка попадает в одну batch каждой epoch;
- последняя batch может быть меньше полного batch;
- повторов внутри одной epoch нет;
- порядок между эпохами новый;
- helper не меняет содержимое buffer;
- helper не делает копию всех sample-массивов.

Тест:

```python
size = 5
batch_size = 2
epochs = 3
```

Ожидаемый результат:

```text
ceil(5 / 2) × 3 = 9 batches
каждый индекс встречается ровно 3 раза
в каждой epoch индексы покрывают {0, 1, 2, 3, 4}
```

samples = self.strategy_buffer.sample(n)

Это вместо текущих `20` random steps.
