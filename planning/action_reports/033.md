# Bug #33: Абсолютное кодирование позиций + hardcoded player_id в choose_action

## Статус: FIXED

## Описание

Функция `encode_state` кодировала позиции (button, current_player, блоки игроков) в абсолютных
seat-id (0..N-1). Это делало обучение single-agent Deep CFR некорректным: при traversing_player=0 сеть
училась видеть hero всегда в слоте player_0, но при использовании сети за opponents hero оказывался
в другом слоте. Также `norm_unit` fallback использовал `players_state[0]` вместо `players_state[player_id]`.

Дополнительно: `DeepCFRAgent.choose_action` использовал `encode_state(state, self.player_id)` —
при shared single-agent подходе (один агент для всех мест) это кодировало state всегда
относительно player_id=0, даже когда агент играл за seat 3 или 5.

## Изменения

### 1. Hero-relative encoding (обе копии encode_state)

| Фича | До (absolute) | После (hero-relative) |
|------|---------------|----------------------|
| button_enc | `button_enc[state.button] = 1` | `button_enc[(state.button - player_id) % N] = 1` |
| current_player_enc | `current_player_enc[state.current_player] = 1` | `current_player_enc[(state.current_player - player_id) % N] = 1` |
| players_state loop | `for p in range(N): state.players_state[p]` | `for offset in range(N): p = (player_id + offset) % N` |
| norm_unit fallback | `players_state[0].stake + ...` | `players_state[player_id].stake + ...` |

Файлы: `src/core/model.py`, `inference/core.py`

### 2. Single-agent training

`traversing_player` всегда 0 (вместо ротации `iteration % num_players`).
Обучается только player 0, оппоненты используют ту же shared strategy.
Random button даёт разные позиции.

Файл: `src/training/train.py`

### 2.1 Один advantage_buffer (вместо 6)

Заменён список из 6 `advantage_buffers` на один `self.advantage_buffer`.
Размер буфера: 16384 (из расчёта ~1400 сэмплов/итерацию × запас 10×).

- `prepare_iteration`: `self.advantage_buffer.clear()`
- `cfr_traverse_multi`: `self.advantage_buffer.add(...)`
- `train_advantage_network_multi`: убран цикл по pid, берёт данные из одного буфера
- `total_advantage_memory_size`: `len(self.advantage_buffer)`
- Диагностика в train.py: убраны `Memory/Advantage_P{pid}`, остался `Memory/Advantage`

Файлы: `src/core/deep_cfr.py`, `src/training/train.py`, `config.yaml`, `src/utils/config.py`

### 3. choose_action с player_id

`DeepCFRAgent.choose_action(state)` → `choose_action(state, player_id=None)`.
При `player_id=None` используется `state.current_player`.
`encode_state` вызывается с переданным `player_id`, а не `self.player_id`.

`scripts/play.py`: `agents[current_player].choose_action(state, player_id=current_player)`.

Файлы: `src/core/deep_cfr.py`, `scripts/play.py`

### 4. Тесты

- `tests/test_relative_encoding.py` — новый: проверяет relative button, relative current_player,
  hero at offset 0, player blocks order, determinism
- `tests/test_field_verification.py` — обновлён: player blocks проверяются по offset, а не по абсолютному p
- Исправлен устаревший `action_type=2` → `3` для Raise в тесте

## Важно

- Длина входа сети не изменилась — 157 для 6 игроков
- Старые checkpoint'ы **несовместимы** — input features поменяли смысл. Обучение нужно начинать заново.
- Rust-среда pokers не менялась
