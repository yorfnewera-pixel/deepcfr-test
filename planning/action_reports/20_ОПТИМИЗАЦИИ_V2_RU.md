## 1. Experiment Tracking — seed + config + git_hash в чекпоинты

### Что сделано
- `DeepCFRAgent.save_model()` — добавлены `seed`, `config` (словарь всех гиперпараметров), `git_hash` (short commit hash)
- `DeepCFRAgent.load_model()` — логирует загруженные метаданные: seed, конфиг, git hash
- `train_self_play_multi()` checkpoint — добавлены те же поля
- argparse: добавлен `--seed` для воспроизводимости
- При `seed=None` — автогенерация и запись в checkpoint

### Что даёт
При загрузке чекпоинта видишь: "обучен с seed=42, lr_adv=1e-4, hidden=256, git=abc1234". Можно воспроизвести эксперимент.

### Файлы
- `src/core/deep_cfr.py`: `save_model()`, `load_model()` (+import os, subprocess)
- `src/training/train.py`: checkpoint save (+import subprocess), argparse `--seed`, seed setup в train_self_play_multi

## 2. Config YAML — config.yaml для гиперпараметров

### Что сделано
- Создан `config.yaml` в корне проекта с ~20 гиперпараметрами
- Создан `src/utils/config.py`: `load_config()`, `cfg_get()`, `cfg_all()`, `_deep_merge()`, `_DEFAULTS`
- `DeepCFRAgent.__init__` — все хардкоды заменены на `cfg_get('key', default)`
- `_DEFAULTS` — fallback если YAML не найден
- `_deep_merge` — конвертация строк из YAML в float/int по типу дефолта

### Что даёт
Меняешь lr, batch_size, buffer — редактируешь YAML, не лезешь в код.

### Файлы
- `config.yaml`: 20 гиперпараметров
- `src/utils/config.py`: новый файл
- `src/utils/__init__.py`: экспорт load_config, cfg_get, cfg_all
- `src/core/deep_cfr.py`: __init__ через cfg_get (+import cfg_get)

## 3. PG-буфер 10K (было 100K)

### Что сделано
- `pg_memory_size` в config.yaml = 10000 (было 100000)
- Дефолт в `_DEFAULTS` = 10000
- `__init__` DeepCFRAgent: `pg_memory_size or cfg_get('pg_memory_size', 10000)`

### Что даёт
Fresher данные для PG-обучения sizing_head. 10K = ~1-2 итерации данных, не 10-20. Меньше policy drift.

### Риск
Если 10K слишком мало — поднять до 20K в config.yaml. Гиперпараметр, не код.

## 4. Suit Isomorphism — First Appearance маппинг

### Что сделано
- Новая функция `_build_suit_canonical_map(hand_cards, public_cards)` в model.py
- Логика: первая масть в руке → canonical 0, вторая → 1, новые с борда → 2, 3
- `encode_state()` — `card_idx = canonical_suit * 13 + int(card.rank)` вместо `int(card.suit) * 13`
- Тесты: `tests/test_suit_isomorphism.py` (4 теста, все пройдены)

### Что даёт
Сеть учит A♠K♠ и A♥K♥ как ОДИН info set. ~4x сокращение уникальных состояний = эквивалентно 4x больше данных без дополнительных traversals.

### Риск
Если маппинг некорректен (масти прыгают между улицами) — сломает обучение. First Appearance гарантирует стабильность: A♠K♠ всегда = As0Ks0 от префлопа до ривера. Без флага отключения (сразу включено).

### Файлы
- `src/core/model.py`: `_build_suit_canonical_map()`, `encode_state()` updated
- `tests/test_suit_isomorphism.py`: новый файл
