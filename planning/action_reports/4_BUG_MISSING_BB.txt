АФФЕКТ
======
pokers State не хранит sb/bb. Python-код проверяет hasattr(state, 'bb'),
не находит → fallback min_raise_increment = 1.0 вместо bb = 2.0.

Последствия:
1. Минрейз = 1.0 вместо 2.0 — агенты могут ставить меньше большого блайнда
2. Некорректный клип: max(1.0, min(additional, remaining)) вместо max(2.0, ...)
3. Искажение CFR: минимальный Raise меньше реального минрейза

ПРИМЕР
======
sb=1.0, bb=2.0, pot=3.0, remaining=198.0

С min_raise=1.0 (БАГ):
  multiplier=0.02 → pot*0.02 = 0.06
  min(0.06, 198) = 0.06
  max(1.0, 0.06) = 1.0  ← Raise $1 — меньше BB!

С min_raise=2.0 (ПРАВИЛЬНО):
  multiplier=0.02 → pot*0.02 = 0.06
  min(0.06, 198) = 0.06
  max(2.0, 0.06) = 2.0  ← Raise $2 = BB — корректно

КОРЕНЬ
======
pokers/src/state.rs: struct State не содержит полей sb/bb.
pokers/src/game_logic.rs: from_deck() получает sb/bb как параметры,
но не сохраняет их в State.

PYTHON-КОД (уже работает после патча)
=====================================

deep_cfr.py:
  min_raise_increment = max(1.0, float(state.bb)) if hasattr(state, 'bb') and state.bb and float(state.bb) > 0 else 1.0

  Теперь hasattr(state, 'bb') = True → min_raise_increment = max(1.0, 2.0) = 2.0 ✓

random_agent.py:
  min_raise = max(1.0, float(state.bb)) if hasattr(state, 'bb') and state.bb and float(state.bb) > 0 else 1.0

  Аналогично → min_raise = 2.0 ✓

ПРИМЕЧАНИЕ: hasattr guard можно упростить до float(state.bb),
но лучше оставить на случай если sb/bb = 0 (маловероятно но безопасно).
