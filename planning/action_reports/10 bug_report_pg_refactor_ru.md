## БАГ #1 [КРИТИЧЕСКИЙ]: MSE-регрессия к использованному сайзингу не ищет оптимальный размер ставки

**Файлы:** `src/core/deep_cfr.py:498-515` (train_advantage_network), `src/core/model.py:30-35` (sizing_head)

**Описание:**
Текущая архитектура обучает `sizing_head` через MSE loss к `bet_size_multiplier`, который был **использован** во время `cfr_traverse`:
```python
bet_size_loss = F.smooth_l1_loss(bet_size_preds, bet_size_tensors, reduction='none')
```

Это принципиально сломанный подход: сеть учится **повторять** тот сайзинг, который сама же и предсказала, а не **оптимизировать** его. Нет обратного сигнала «было ли это хорошим размером ставки?».

**Аналогия:** Это как обучать игрока в покер, показывая ему «ты поставил 2x пот — запомни это значение», вместо «ты поставил 2x пот и проиграл — попробуй в следующий раз поставить иначе».

**Почему это ломает обучение:**
1. **Циклическая зависимость:** sizing_head предсказывает значение → это значение используется в траверсе → это же значение становится target для MSE → сеть подтягивается к собственному предсказанию → нет давления к изменению.
2. **Отсутствие градиента качества:** MSE loss = 0 когда `prediction == target` — но target — это не оптимальный сайзинг, а просто использованный. Нет разницы между «предсказал 1.5x и это было хорошо» и «предсказал 1.5x и это было ужасно».
3. **Сходимость к среднему:** Сеть сходится к среднему значению использованных сайзингов, а не к контекстно-оптимальному.

**Воспроизведение:**
1. Обучить модель 1000+ итераций
2. Проверить распределение предсказанных bet_size — оно будет сжатым вокруг среднего (≈1.5x), без адаптации к стадии руки, позиции и т.д.
3. Сравнить profit при фиксированном сайзинге 1.5x vs предсказанном — разница минимальна

**Фикс:** Policy Gradient с reward = EV Raise-ветки (action_values[2]). PG даёт сигнал «этот сайзинг привёл к высокому EV — усиливай его».

## БАГ #2 [КРИТИЧЕСКИЙ]: Нет исследования (exploration) пространства сайзинга

**Файлы:** `src/core/deep_cfr.py:326-328`, `src/core/model.py:33-34`

**Описание:**
Текущая `sizing_head` — детерминированная функция:
```python
self.sizing_head = nn.Sequential(
    nn.Linear(hidden_size, hidden_size // 2),
    nn.Tanh(),
    nn.Linear(hidden_size // 2, 1),
    nn.Sigmoid()  # Всегда одно и то же значение для одного и того же входа
)
```

Для одного и того же состояния сеть ВСЕГДА предсказывает один и тот же bet_size_multiplier. Нет механизма для исследования альтернативных сайзингов.

**Почему это критично:**
- В покере один и тот же state может требовать **разных** сайзингов в зависимости от стратегии оппонента (например, против тайтового оппонента — больше блефовых рейзов, против лузового — больше велью-рейзов)
- Без exploration сеть никогда не «попробует» бет 2.5x если она уже сошлась к 1.5x — даже если 2.5x было бы выгоднее
- Слежение (observational learning) через CFR регреты работает для **типа действия** (Fold/Call/Raise), но не для **непрерывного параметра** — регреты вычисляются только по дискретным action_type

**Фикс:** Sizing_head предсказывает параметры Normal распределения (mean, log_std), сэмплирование из Normal во время cfr_traverse обеспечивает exploration, энтропийный бонус предотвращает схлопывание.

## БАГ #3 [ВЫСОКИЙ]: CFR регреты не влияют на выбор размера ставки

**Файлы:** `src/core/deep_cfr.py:381-416`, `src/core/deep_cfr.py:498-515`

**Описание:**
Deep CFR вычисляет контрфактуальные регреты для каждого `action_type` (0=Fold, 1=Call, 2=Raise). Однако для Raise с непрерывным размером ставки:

1. В `cfr_traverse` размер ставки **фиксирован** для всего информационного множества — сеть предсказывает один `bet_size_multiplier` и использует его для ВСЕХ Raise-веток.
2. Регрет для `action_type=2` — это «насколько Raise в среднем был лучше/хуже смешанной стратегии». Но он **не дифференцирует** по размеру ставки: «Raise 1x pot с регретом +5» и «Raise 3x pot с регретом +5» — для системы одно и то же.
3. В `train_advantage_network` sizing loss (MSE) и regret loss обучаются **независимо** — sizing просто копирует использованное значение, а regret предсказывает «насколько Raise лучше Fold/Call».

**Результат:** Сеть может «выучить» что Raise — хорошее действие (положительный регрет), но никогда не узнает, **какой именно размер рейза** максимизирует EV.

**Фикс:** PG-лосс привязывает sizing к reward (EV Raise-ветки): «Raise 2.5x привёл к EV=+10 → усиливай log_prob для 2.5x в этом состоянии».

## БАГ #4 [ВЫСОКИЙ]: Gradient conflict — sizing_head и action_head делят бэкбон

**Файлы:** `src/core/model.py:19-35`, `src/core/deep_cfr.py:518-524`

**Описание:**
В `PokerNetwork` sizing_head и action_head **делят общий бэкбон** (`self.base`). В `train_advantage_network`:

```python
combined_loss = weighted_action_loss + 0.5 * weighted_bet_size_loss
combined_loss.backward()  # Обновляет ВСЕ параметры, включая base
```

Один и тот же `backward()` обновляет бэкбон градиентами от обоих лоссов. Проблема:
- **Action loss** (regret prediction) — основная задача Deep CFR, требует точного предсказания регретов
- **Sizing loss** (MSE regression) — побочная задача, с шумным target (см. БАГ #1), может «тянуть» бэкбон в неправильную сторону

**Сценарий конфликта:** На ранних итерациях sizing loss может быть большим (сеть ещё не сошлась к среднему сайзингу). Градиенты от sizing loss «заглушают» градиенты от action loss в общих слоях → регрет-предсказание обучается медленнее → стратегия хуже → данные хуже → порочный круг.

**Фикс:** `features.detach()` при передаче в sizing_head — sizing обновляет только свою голову, бэкбон обучается исключительно через CFR loss. Отдельный PG-оптимизатор для sizing_head.

## БАГ #5 [СРЕДНИЙ]: Strategy_net копирует сломанный sizing через MSE к «использованному» значению

**Файлы:** `src/core/deep_cfr.py:593-616`

**Описание:**
`train_strategy_network` обучает sizing в strategy_net тем же сломанным MSE:
```python
bet_size_loss = F.smooth_l1_loss(raise_bet_preds, raise_bet_targets, reduction='none')
```

Где `raise_bet_targets` — это bet_size из `strategy_memory`, который был **сэмплирован** из advantage_net. Проблемы:
1. Target — это не оптимальный сайзинг, а «что предсказала advantage_net на тот момент»
2. Strategy_net учится «быть как advantage_net» — но advantage_net не знает оптимального сайзинга (см. БАГ #1)
3. Дистилляция сломанного знания → сломанная стратегия

**Фикс:** Strategy_net обучается MSE к `mean` из PG-буфера. После того как PG нашёл оптимальный mean для каждого состояния, strategy_net дистиллирует это знание в детерминированную игровую политику.

## БАГ #6 [СРЕДНИЙ]: Нет мониторинга качества сайзинга — невозможно обнаружить стагнацию

**Файлы:** `src/training/train.py` (TensorBoard логирование)

**Описание:**
В TensorBoard логируются:
- `Loss/Advantage` — общий лосс (включая sizing MSE)
- `Loss/Strategy` — общий лосс strategy net

Нет отдельных метрик для sizing:
- Какой средний предсказанный bet_size? (может застрять на 1.5x)
- Насколько разнообразны предсказания? (может сжаться к одному значению)
- Какой contribution sizing loss в общий лосс?

Без этих метрик невозможно обнаружить:
- **Стагнацию:** sizing_head сошлась к одному значению и не меняется
- **Доминирование:** sizing loss заглушает action loss
- **Бесполезность:** предсказанный сайзинг не влияет на profit (всегда ~1.5x)

**Фикс:** Логировать: `Sizing/Mean_Predicted_Size`, `Sizing/Mean_Standard_Deviation`, `PG/MeanEntropy`, `Loss/PG` отдельно.

## БАГ #7 [СРЕДНИЙ]: Sizing_head с Sigmoid ограничивает репрезентативную мощность

**Файл:** `src/core/model.py:33-34`

**Описание:**
```python
nn.Sigmoid()  # Output between 0-1
...
bet_size = 0.1 + 2.9 * self.sizing_head(features)  # [0.1, 3.0]
```

Проблемы с Sigmoid для регрессии:
1. **Насыщение градиентов:** Sigmoid насыщается при значениях близких к 0 или 1 → градиенты близки к нулю → сеть «застревает» у краёв диапазона
2. **Не-центрированный output:** Sigmoid центр в 0.5 → bet_size центр в 1.55x — сеть «подтягивается» к середине диапазона, а не к оптимальному значению
3. **Нет неопределённости:** Один детерминированный выход — сеть не может выразить «я не уверен, может быть 1x или 2.5x»

**Фикс:** Gaussian policy: `mean = 0.1 + 2.9 * sigmoid(mean_raw)`, `log_std = clamp(log_std_raw, -5, 1)`. Mean — лучшая оценка, std — неопределённость, сэмплирование — exploration.
