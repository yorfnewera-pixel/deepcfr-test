# Bug #32: Миграция с 3 на 4 действия

## Статус: FIXED

## Контекст миграции

**До**: 3 действия — `Fold(0), Check/Call(1), Raise(2)`. Check и Call были слиты в 1 слот,
т.к. взаимоисключающие по правилам покера (min_bet==0 → только Check, min_bet>0 → только Call).
Fold при Check маскировался на уровне Python как «строго доминируемая стратегия».

**После**: 4 действия — `Fold(0), Check(1), Call(2), Raise(3)`. Check/Call разделены на
отдельные слоты. Fold при Check убран на уровне Rust-среды (взаимоисключение как у Check/Call).

**Причина миграции**: При 3 действиях маска Fold/Check была стратегическим решением
(Python-уровень), а не механическим правилом среды. Это создавало расхождение между
средой (Fold легален всегда) и маской (Fold запрещён при Check). Патч Rust-среды
убирает Fold при min_bet==0 — теперь Check/Fold взаимоисключающие как Check/Call,
и маска становится прямым отражением legal_actions без доминирования.

## Ошибка (недочёт миграции)

При миграции часть файлов не была обновлена:

### `src/opponent_modeling/deep_cfr_with_opponent_modeling.py`
- `num_actions = 3` вместо 4
- Комментарий "Fold, Check/Call, Raise" вместо "Fold, Check, Call, Raise"
- `action_type == 2` для Raise вместо `action_type == 3`
- `Check or Call → action_id = 1` — слипание Check/Call в один action_id
- `action_id = 2` для Raise вместо `action_id = 3`
- `raise_mask = (action_type_tensors == 2)` вместо `== 3`
- `raise_mask = (strategy_tensors[:, 2] > 0)` вместо `[:, 3]`
- `bet_size_multiplier if 2 in legal_action_types` вместо `3`

### `inference/adapters/pokers.py`
- `labels = {0: "Fold", 1: "Check/Call", 2: "Raise"}` — старые 3-слотные лейблы

## Исправление

Все упомянутые места обновлены до 4 действий.
Raise теперь `action_type == 3` везде. Check = 1, Call = 2 — раздельно.
