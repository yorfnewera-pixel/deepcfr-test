# ТЗ: опциональный D2CFR в существующем DeepCFR-проекте

## Цель

Добавить D2CFR-режим, включаемый через `config.yaml`:

```yaml
d2cfr_enabled: false
```

При `false` существующий алгоритм, обучение, инференс и загрузка checkpoint должны работать как прежде.

При `true` использовать dueling-сеть с явным обучением ценности состояния и действий, из которых формируются regret-предсказания.

**Не внедрять одновременно:**

- OS-обход;
- history-Q baseline из VR-DeepDCFR+;
- Rainbow DQN-компоненты;
- отсечение дерева через value-сеть;
- новую teacher–student дистилляцию;
- переделку GUI и игрового движка.

Использовать существующий ES-обход и контракт `six_fixed_v2`.

## 1. Сначала проверить актуальную реализацию

Перед изменениями прочитать:

- `src/core/model.py`;
- `src/core/deep_cfr.py`;
- `src/core/buffers.py`;
- `src/training/train.py`;
- `src/utils/config.py`;
- загрузчики checkpoint для оценки и инференса;
- тесты обучения и checkpoint.

Сверить D2CFR с разделом III и алгоритмами статьи:  

https://arxiv.org/html/2105.12328v2

**Не копировать неоднозначные формулы автоматически.** В частности, отдельно проверить описание обучения value-ветви, MC-весов и знак KL-регуляризации. Не добавлять KL в этот этап.

## 2. Добавить конфигурацию

Предлагаемые новые параметры:

```yaml
# По умолчанию сохраняется существующий алгоритм.
d2cfr_enabled: false

# Относительные веса новых обучающих задач.
# Стартовые значения для эксперимента, не заявленные параметры статьи.
d2cfr_regret_loss_weight: 1.0
d2cfr_state_value_loss_weight: 1.0
d2cfr_action_value_loss_weight: 1.0

# Для D2CFR-подобного обучения по историческим сэмплам.
d2cfr_reinitialize_each_iteration: true
d2cfr_iteration_weight_power: 1.0

# MC-коррекция — отдельный этап, не включать неявно.
d2cfr_mc_correction_enabled: false
```

Добавить значения по умолчанию в `src/utils/config.py`.

**Не создавать фиктивный работающий флаг:** пока MC-коррекция не реализована, значение `true` должно вызывать понятную ошибку, а не игнорироваться.

При старте явно выводить:

- выбранный алгоритм;
- тип обучающих целей;
- включена ли MC-коррекция;
- какие параметры текущего DCFR в этом режиме не используются.

## 3. Добавить отдельную dueling-модель

Существующий `PokerNetwork` не менять по смыслу.

Добавить отдельный класс, например `DuelingRegretNetwork`:

```
encoded infoset
       ↓
shared feature extractor
       ├── state-value branch  → V(I)
       └── action-value branch → Q(I, a)

regret prediction:
       R̂(I, a) = Q(I, a) − V(I)
```

Здесь `Q(I,a)` — **ветвь оценки действий по информации игрока**, а не отдельная privileged history-Q сеть.

Требования:

- тот же encoder и размер action space;
- не читать скрытые карты оппонента;
- legal mask применять в loss и regret matching;
- сохранить внешний интерфейс: обычный `forward()` возвращает вектор regret-предсказаний;
- дополнительный метод возвращает `state_value`, `action_values`, `regrets` для обучения.

**Не применять автоматически стандартную DQN-формулу центрирования по среднему всех действий.** В CFR ценность текущей стратегии — взвешенная по её вероятностям величина, а не обязательно равномерное среднее.

## 4. Использовать данные, уже получаемые ES-обходом

В узле traverser уже вычисляются:

```
action_values[a] = результат рекурсивного обхода действия a
state_value = Σ strategy[a] × action_values[a]
instant_regrets[a] = action_values[a] − state_value
```

Для D2CFR дополнительно сохранять:

```
encoded_state
action_values
state_value
instant_regrets
legal_mask
iteration
```

**Не запускать дополнительные симуляции ради этих целей:** они уже доступны после текущего обхода.

Все значения должны использовать один масштаб наград. Не допускать ситуации, когда regrets делятся на `advantage_reward_scale`, а value-цели остаются в фишках.

Зависящие от узла преобразования и clipping должны быть согласованы. Если комбинация не поддержана, отклонять её конфигурационной проверкой.

## 5. Добавить D2CFR-буфер и отдельную ветку loss

Рекомендуется новый класс буфера, чтобы не ломать старый формат.

Для D2CFR-режима:

- historical reservoir sampling;
- данные предыдущих итераций сохраняются;
- номер итерации используется для весов;
- write position, число увиденных сэмплов и фактический размер учитываются корректно.

**Не использовать очистку advantage-буфера из bootstrap-DCFR для этого буфера.** При нескольких traversing players не терять данные предыдущих игроков.

Обучение:

```
L =
    λr × masked_MSE(predicted_regrets, sampled_regrets)
  + λv × MSE(predicted_state_value, sampled_state_value)
  + λq × masked_MSE(predicted_action_values, sampled_action_values)
```

Применять согласованные временные веса к сэмплам всех задач.

Это явная, проверяемая схема совместного обучения. **Точные вспомогательные loss и их веса нужно обозначить как инженерную конкретизацию, если авторская реализация не подтверждает их буквально.**

Важно: обучение только разности `Q−V` не определяет смысл `V` однозначно. Value-ветви нужна собственная обучающая цель.

## 6. Не смешивать два способа накопления regrets

Развести режимы:

```
d2cfr_enabled = false:
    существующие targets из advantage_target_net
    существующие discount/clamp
    существующий жизненный цикл буфера

d2cfr_enabled = true:
    исторические sampled-regret/value цели
    взвешенное обучение dueling-модели
    без bootstrap-сложения с advantage_target_net
```

**Не добавлять текущую state value к накопленному advantage и не вычитать её из него.**

Включение D2CFR должно сопровождаться понятным сообщением, что параметры `advantage_accumulation` и `discount_alpha` старого режима не участвуют в новом advantage-loss.

Гибрид D2CFR + DCFR+ — отдельная будущая задача, не скрытая часть этого изменения.

## 7. Минимально интегрировать в текущий агент

Сохранить общие методы:

- выбор действия;
- вычисление legal mask;
- ES traversal;
- обучение strategy;
- оценку и сохранение.

Различия спрятать в небольших точках:

```
создание advantage-модели
запись обучающего сэмпла
подготовка буфера к итерации
обучение advantage-модели
сериализация
```

Не копировать целиком `DeepCFRAgent` или `train_self_play_multi`.

**Этот флаг сам по себе не должен незаметно менять opponent pool или число обучаемых игроков.** Но при запуске с историческими оппонентами или общей сетью явно обозначать результат как адаптацию D2CFR, а не точное воспроизведение HU-алгоритма статьи.

Исправление сбора average-policy сэмплов учитывать отдельно: нельзя объявлять новую strategy-сеть paper-faithful, оставив несогласованный способ её усреднения.

## 8. Checkpoint и инференс

Добавить метаданные:

```
algorithm_variant
network_architecture
training_target_semantics
d2cfr_config
```

Требования:

- старые checkpoint продолжают загружаться старым путём;
- новый full checkpoint восстанавливает dueling-сеть, оптимизатор и D2CFR-буфер;
- несовместимая загрузка выдаёт понятную ошибку;
- нельзя молча загружать обычный action head в dueling-модель;
- light checkpoint сохраняет strategy-сеть в совместимом формате, если её архитектура не менялась;
- загрузчики advantage-сетей оппонентов учитывают новый тип модели.

## 9. Тесты и критерии готовности

Обязательные проверки:

- **Флаг выключен:** старые модели, targets и checkpoint работают без изменений.
- **Флаг включён:** сеть возвращает корректные формы и конечные значения.
- **Цели согласованы:** `regret = action_value − state_value`.
- **Маски:** нелегальные действия не участвуют в loss и выборе.
- **Градиенты:** обе ветви и общий extractor обучаются.
- **Буфер:** исторические данные сохраняются, reservoir работает после заполнения.
- **Несколько игроков:** сэмплы одного игрока не стираются сбором следующего.
- **Checkpoint:** сохранение и восстановление не меняют предсказания.
- **Smoke test:** короткое HU-обучение с обоими значениями флага.
- **Бюджет:** измеряется полное время итерации, а не только новый loss.

Добавить отдельные метрики regret-, state-value- и action-value-loss. **Не считать снижение вспомогательного loss доказательством усиления стратегии.**
