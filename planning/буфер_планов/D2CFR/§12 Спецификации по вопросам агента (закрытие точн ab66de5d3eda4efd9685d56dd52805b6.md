## 1. Baseline: формулы и исправление §4

<aside>
❌

Замечание верное, §4 сформулирован неверно. Baseline **не является** drop-in заменой скаляра `v_MC(I)` внутри смешивания `α·v_NN + β·v_MC`. Это другой уровень вмешательства: baseline встраивается в сам обход дерева и меняет то, как вычисляются сами counterfactual values, из которых потом строятся цели сети.

</aside>

### 1.1 Формулы (VR-MCCFR, Schmid et al. 2019, arXiv:1809.03057)

Рекурсивная оценка с bootstrapping, без baseline:

```
û_i(σ, h, a | z) = û_i(σ, ha | z) / ξ(h, a)   если ha ⊑ z
                 = 0                          иначе
```

Baseline-enhanced версия `û^b_i(σ, h, a | z)` — тот же контрольный вариат, что и в DREAM уравнении (4) ниже. Счётные counterfactual values для regret-апдейта — уравнение (18):

```
v̂^b_i(σ, I(h), a | z) = [ π^σ_{−i}(h) / q(h) ] · û^b_i(σ, h, a | z)
```

**Lemma 2:** `E_z[v̂^b_i(σ, I, a | z)] = v_i(σ, I, a)` — несмещённость сохраняется при **любом** `b_i(I,a)`, включая bootstrap из других оценок внутри того же эпизода. Качество baseline влияет только на дисперсию и скорость сходимости, не на смещённость. **Lemma 3:** существует идеальный `b*`, при котором дисперсия ровно нуль.

Табличный выбор baseline у авторов — экспоненциально затухающее среднее `ũ_i(I, a)` по посещениям, коэффициент затухания `α = 0.5`, сэмплирование равномерное `ξ(I,a) = 1/|A(I)|`.

### 1.2 Форма для реализации (DREAM, уравнение (4))

Берём за референс именно эту запись — она в терминах infostate и прямо кодируется:

```
ṽ_i(h, a | z) = b_i(h, a) + [ Σ_{h'} p(h' | T(h, a, π_{−i})) · ṽ_i(h' | z) − b_i(h, a) ] / ξ_i(s_i, a)
                 если a — сэмплированное действие
ṽ_i(h, a | z) = b_i(h, a)   иначе

ṽ_i(h | z) = R_i(h)                              если h = z (терминал)
ṽ_i(h | z) = Σ_a π_i(h, a) · ṽ_i(h, a | z)        иначе
```

Ключевое: делится на `ξ` только **разность** с baseline, а не вся оценка. Несэмплированные действия получают `b`, а не нуль — это и есть вся разница с обычным MCCFR.

Baseline в DREAM — обучаемая Q-сеть, а не таблица. Дополнительные веса:

- сэмплы advantage-буфера взвешиваются при обучении на `1 / x^ξ_i(s_i)` — компенсация сдвига распределения из-за `ε`-исследования
- сэмплы average-policy буфера — на `1 / x^ξ_{−i}(h)`

Сходимость: результаты MC-CFR держатся для любого несмещённого оценщика state-action values, поэтому произвольный baseline допустим.

### 1.3 Исправленное решение вместо §4

Разводим два независимых механизма, которые в §4 были ошибочно слеплены:

| Механизм | Флаг | Что делает | Статус |
| --- | --- | --- | --- |
| MC rectification по статье | `d2cfr_mc_correction_enabled` | Смешивание `α·v_NN + β·v_MC`, `N = 800` роллаутов, затухание до `t ≥ 99` | Буквально по статье, только HU/Leduc. Дефолт `false` |
| Variance reduction в обходе | `traversal_baseline_enabled` | Baseline-corrected `ṽ` по формулам §1.2 внутри traversal | **Отклонение от статьи.** Дефолт `false` |

Их нельзя включать одновременно без отдельного анализа — assert на взаимоисключение.

Важное уточнение по нашему контексту: формулы выше записаны для **outcome sampling**. У нас **external sampling**, где все действия traverser перебираются полностью, то есть нет несэмплированных действий траверсера → выигрыш от baseline есть только на chance-узлах и действиях оппонента. **Сначала измерить дисперсию в текущем ES и только потом решать, нужен ли baseline вообще.** Это не блокер HU-ядра.

<aside>
📝

Вывод: для закрытия HU-ядра baseline **не критичен**. Критичным он казался только потому, что §4 ошибочно сделал его дефолтным бэкендом rectification. Порядок: HU-ядро без rectification → замер дисперсии → решение по baseline.

</aside>

## 2. DNet: буквальный вариант — дефолт

Замечание верное. Решение: `d2cfr_dueling_aggregator` с двумя значениями.

- **`literal`** (дефолт) — две головы, `r(I,a) = V(I,a) − V(I)`, без mean-subtraction. Единственный вариант, про который можно говорить «репликация D2CFR».
- **`mean_subtract`** — `Q = V + (A − mean_a A)`. Осознанная вариация, только для экспериментов по стабильности. В логах и в отчётах помечать как `variant: non-literal`.

Почему буквальный вариант здесь корректен, а в Dueling DQN нет: в DQN есть только супервизия на `Q`, поэтому разложение `V + A` неидентифицируемо и требует якоря. У нас `V` получает свою отдельную цель `V_target(I) = Σ_a σ(I,a)·Q_target(I,a)`, то есть голова `V` идентифицирована супервизией → якорь не нужен.

Про Fig. 4: в D2CFR схема dueling-сети не добавляет информации поверх формулы из текста — текстовая формула авторитативнее рисунка. Если нужна визуальная сверка — приложить скрин страницы с DNet из PDF отдельно.

## 3. Контракт лосса — §3 переписан

<aside>
❌

Замечание верное, и оно вскрыло ошибку. Моррилл нормализует **накопленный** regret (`R̄^T = R^T/T`), а сеть D2CFR учится на **мгновенных** regrets `r̃^{t'}` из reservoir. Делить мгновенные regrets на `t` — бессмысленно и опасно: в буфере лежат сэмплы с разными `t'`, и деление внесло бы разные масштабы внутри одного батча. **Пункт «делить на `t`» отменяется.** Фрагмент Моррилла больше не нужен.

</aside>

Полный контракт:

1. **Что предсказывает сеть.** `r_NN(I, a | θ)` — мгновенный counterfactual regret в масштабе нормализованных выплат. Не накопленный, не средний.
2. **Масштаб целей.** Единственное преобразование — payoff scaling `u → u / L`, `L = max|u|`, применяется один раз на выходе игры, до traversal. Тогда `u ∈ [−1, 1]` и `r̃ ∈ [−2, 2]`. Больше никаких делений целей нет.
3. **Вес в reservoir-loss.** Остаётся множитель из Alg. 1, но в нормализованном виде `w(t') = (t'/T)^p`, `p = 1.0`. При `p = 1` это `t'/T` — тот же `t'` с общим положительным коэффициентом `1/T`, то есть аргминимум лосса не меняется, меняется только масштаб градиента. Вес — скаляр перед каждым слагаемым, не перед суммой.
4. **Инвариантность RM.** `σ(a) = R⁺(a) / Σ_{a'} R⁺(a')`. Для любого `c > 0`: `(cR)⁺ = c·R⁺` → `c` сокращается в числителе и знаменателе. Поэтому payoff scaling не меняет политику, только обусловленность обучения. Важно: инвариантность выполняется только для **общего** масштаба по всем действиям одного инфосета — отсюда требование единого `L` глобально, а не per-infostate.
5. **Где запрет.** В коде не должно быть ни одного места, где к regret-цели применяется деление на номер итерации, `√t`, или на сумму reach-вероятностей (это механика Deep CFR / DNCFR, не D2CFR). RED-тест на это.

Стабилизация (Huber, grad-clip 1.0, отсутствие norm на выходе) остаётся без изменений и к нормализации целей отношения не имеет.

## 4. Гарантия rectification: отказ от заявления

Замечание верное. Фиксируем прямо:

<aside>
⚠️

Мы **не заявляем** сохранение теоретической гарантии D2CFR для rectification. Доказательство авторов опирается на `V_MC(I) ≥ 0`, а наша нормализация выплат в `[−1, 1]` это предположение нарушает.

</aside>

Почему не исправляем сдвигом в `[0, 1]`: аффинный сдвиг выплат ломает zero-sum свойство и меняет counterfactual values неоднородно по инфосетам (reach-вероятности разные) — лекарство хуже болезни.

Статус помечается в логах: `MC rectification: heuristic (no theoretical claim)`. Если гарантия когда-нибудь понадобится — нужен supplementary material с IEEE Xplore, формула (63) и разделы C-A/C-B. Сейчас это не блокер, т.к. само rectification выключено по умолчанию.

## 5. `discount_gamma`: жёсткое отключение

Замечание верное, формулировка в §0 основного плана («`discount_gamma` влияет только на веса average strategy») — legacy-описание из DCFR+ режима и в D2CFR неверна.

В D2CFR average-strategy лосс имеет свой собственный вес `t'` (Alg. 1, строка 12). DCFR-discount там не задан вообще. Решение:

- при `d2cfr_enabled: true` вес average strategy = `(t'/T)^p`, тот же, что у regret-лосса
- `discount_gamma` **игнорируется полностью**; если задан явно — `ValueError` на старте, а не warning (тихое игнорирование уже один раз привело к путанице)
- то же для `discount_alpha` и `advantage_accumulation`
- проверка выносится в валидатор конфига (`src/utils/config.py`), а не в тело тренинга

Одновременное присутствие `t'` и DCFR-discount в коде = самодельный гибрид, что запрещено §0.

## 6. Policy-KL: хранение истории

Замечание верное: источник здесь не поможет, решаем сами. Выбрано: **ring buffer из `c = 10` замороженных snapshot’ов policy-сети**.

- после каждой итерации кладём `state_dict` policy-сети в кольцевой буфер длины 10
- референсное распределение для батча = среднее арифметическое вероятностных векторов, полученных forward-проходом через все snapshot’ы под `no_grad`
- градиент течёт только через текущую сеть
- на итерациях `t < c` среднее берётся по доступным snapshot’ам; при `t = 0` член нулевой

Почему не распределения на сэмплах из `M_Π`: там для конкретного `I` обычно нет записей во всех 10 последних итерациях (reservoir прореживает), среднее считалось бы по разному числу членов для разных инфосетов — формула перестаёт быть определённой.

Цена: policy-сеть — 7 FC-слоёв, 10 копий дешёвы по памяти; 10 дополнительных forward на батч заметны по времени — ещё один аргумент держать флаг выключенным вне A/B.
