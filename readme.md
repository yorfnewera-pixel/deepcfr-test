# DeepCFR 8-max MTT

Исследовательский проект по обучению агента для freezeout MTT в No-Limit
Texas Hold'em. Целевой режим — один стол героя максимум на **8 игроков** и
оценка решений по ожидаемой итоговой турнирной выплате ($EV), а не по числу
выигранных фишек.

> Статус: целевая MTT-архитектура описана в
> [`planning/МТТ/МТТ План.txt`](planning/%D0%9C%D0%A2%D0%A2/%D0%9C%D0%A2%D0%A2%20%D0%9F%D0%BB%D0%B0%D0%BD.txt).
> Текущий код содержит прежний HU-контур; он сохраняется отдельно и не
> является основой или инициализацией будущего MTT-агента.

## Цель

Создать обучаемого 8-max MTT-агента, который:

- играет полные независимые турнирные эпизоды до вылета или победы;
- учитывает блайнды, ante, структуру выплат, число оставшихся игроков,
  эффективные стеки и агрегированное состояние поля;
- обучается на фактических итоговых выплатах турнира;
- использует локальный MCCFR/Deep CFR для сравнения действий внутри текущей
  раздачи;
- подставляет оценку будущей турнирной ценности на границе завершённой
  раздачи.

Проект не заявляет математическое решение MTT. Его первая цель —
воспроизводимый исследовательский агент и проверяемая среда для экспериментов.

## Граница симуляции

Точно моделируются:

- одна текущая раздача за столом героя, максимум на 8 мест;
- карты, позиции, легальные действия, банк и стеки игроков этого стола;
- блайнды, ante, рассадка, вылеты и пересадки;
- финальный стол: когда в турнире остаётся не более восьми игроков, все они
  должны находиться за подробно симулируемым столом.

Остальное поле не разыгрывается как набор покерных раздач. Оно представлено
агрегированным распределением стеков и стохастическими событиями: вылетами,
изменениями стеков и пересадками. Это сохраняет вычислительный бюджет для
решений героя и не подменяет модель турнира множеством неиспользуемых столов.

## Целевая архитектура

```text
Наблюдение героя
        |
        +-- Local 8-max solver
        |     MCCFR / Deep CFR внутри текущей раздачи
        |
        +-- Tournament state
        |     выплаты, стадия, блайнды, players left,
        |     стеки текущего стола и агрегаты поля
        |
        +-- Field transition model
        |     вероятностный переход агрегированного поля
        |
        +-- Tournament value V$_
              ожидаемая итоговая выплата из следующего состояния
```

Полное состояние известно только среде. Policy и value-функция получают лишь
наблюдаемую игроком информацию; скрытые карты соперников и внутренние
параметры генератора поля им недоступны.

## Награда и обучение

Единственная конечная награда — выплата по таблице призов. Бабл и близость к
оплачиваемым местам — признаки состояния, которые меняют стоимость риска, но
не самостоятельная цель оптимизации.

Эпизод завершается при вылете героя или завершении турнира. После этого
запускается новый независимый турнир. На полных эпизодах сначала обучается
турнирная value-функция `V$_`, а затем локальный solver использует её для
оценки завершённых раздач. Если герой вылетает, вместо `V$_` возвращается его
фактическая выплата.

Нельзя напрямую переносить прежние regrets, policy или replay-буферы в MTT:
изменилась utility и сама постановка задачи. Начальная контрольная policy
нужна только для получения корректных полных MTT-эпизодов.

## Инварианты среды

- В freezeout число участников не увеличивается.
- Фишки не создаются и не исчезают при раздачах, вылетах и пересадках.
- Число игроков за столом и в поле согласовано.
- Средний стек вычисляется из числа участников и общего числа фишек.
- Вылет героя немедленно завершает его эпизод.
- При фиксированных конфигурации, seed и политиках последовательность
  состояний и итоговая выплата воспроизводимы.

## Порядок реализации

1. Зафиксировать правила одного freezeout-формата: выплаты, уровни блайндов,
   пересадки и границы наблюдения.
2. Реализовать турнирную среду: один 8-max стол героя и агрегированное поле;
   покрыть инварианты property-тестами.
3. Реализовать полные эпизоды, выплаты и воспроизводимые журналы.
4. Добавить фиксированные baseline-политики и измерение $EV.
5. Обучить и откалибровать `V$_` на отложенных турнирах.
6. Подключить локальный MCCFR с терминальной utility через `V$_`.
7. Добавить версионированный внешний цикл обучения policy, value-функции и
   модели поля, а также checkpoint/resume.
8. Оценить прирост фактического $EV и провести абляции в той же 8-max
   MTT-среде.

## Установка текущего окружения

Требуется Python 3.8+.

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd deepcfr-test
python -m venv .venv
python -m pip install -r requirements.txt
python -m pip install ./pokers
```

Локальный пакет `pokers` содержит патчи, необходимые проекту.
